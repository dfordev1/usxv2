## What this does NOT cover

- **No cryptographic integrity hashes are recorded for the downloaded SQLite/JSON
  source files themselves** (only for the reconstructed verse text, via
  `checksum-verify.js`). If QUL updates a resource, there's currently no way to
  detect that this repo's copy has gone stale from that specific file's checksum
  alone.
- **No confirmation was sought directly from QUL/TarteelAI, Quranpedia, or
  spqrxi** beyond reading each source's own published statements/files. If you plan
  to redistribute this repo's `data/` directory further (not just use it locally),
  verify current terms with each source yourself rather than relying solely on this
  table.
- This file was written as part of addressing a third-party audit's licensing
  concerns (see `README.md` Known gaps) — it is a good-faith best effort at
  transparency, not a legal clearance.
